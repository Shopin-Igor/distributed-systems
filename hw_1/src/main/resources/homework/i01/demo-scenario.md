# Демонстрационный сценарий работы системы

## Подготовка к демонстрации

### 1. Сборка проекта
```bash
./gradlew build
```

### 2. Проверка конфигурации
Убедитесь, что файл `balancer-config.json` содержит корректные настройки:
- Балансировщик на порту 9999
- Контрольный канал на порту 9090
- Три серверных узла на портах 9001, 9002, 9003

### 3. Остановка всех процессов (при необходимости)
```bash
# Остановить все Java процессы (балансировщик, серверы, клиенты)
taskkill /f /im java.exe

# Альтернативно через PowerShell:
Stop-Process -Name "java" -Force
```

### 4. Просмотр активных процессов
```bash
# Все Java процессы
tasklist | findstr java

# Порт балансировщика
netstat -ano | findstr :9999

# Порты серверов
netstat -ano | findstr :9001
netstat -ano | findstr :9002
netstat -ano | findstr :9003

# Все активные подключения
netstat -ano | findstr ESTABLISHED
# но тут будут вообще все процессы на компьютере

# Детальная информация по портам серверов
netstat -ano | findstr :9001
netstat -ano | findstr :9002  
netstat -ano | findstr :9003

# Проверка состояния соединений
netstat -ano | findstr CLOSE_WAIT
netstat -ano | findstr FIN_WAIT
```

## Часть 1: Базовая функциональность

### Демонстрация Round-Robin балансировки

**Шаги:**
1. Запустите балансировщик:
   ```bash
   java -cp build/libs/* ru.hse.drip.systems.distributed.seminar.i3.balancer.SimpleLoadBalancer balancer-config.json
   ```

2. Запустите все три серверных узла в отдельных терминалах:
   ```bash
   # Терминал 1
   java -cp build/libs/* ru.hse.drip.systems.distributed.seminar.i3.ChatServerMain A 9001
   
   # Терминал 2  
   java -cp build/libs/* ru.hse.drip.systems.distributed.seminar.i3.ChatServerMain B 9002
   
   # Терминал 3
   java -cp build/libs/* ru.hse.drip.systems.distributed.seminar.i3.ChatServerMain C 9003
   ```

3. Подключите несколько клиентов:
   ```bash
   # Терминал 4
   java -cp build/libs/* ru.hse.drip.systems.distributed.seminar.i3.ChatClient
   
   # Терминал 5
   java -cp build/libs/* ru.hse.drip.systems.distributed.seminar.i3.ChatClient
   ```

**Ожидаемый результат:**
- Клиенты подключаются к балансировщику на порту 9999
- Балансировщик распределяет клиентов между серверами A, B, C по алгоритму Round-Robin
- В логах балансировщика видно: "живых=3"

### Демонстрация Health-Check

**Шаги:**
1. Остановите один из серверов (например, сервер B на порту 9002)
2. Подождите 10-15 секунд
3. Подключите нового клиента

**Ожидаемый результат:**
- В логах балансировщика: "живых=2"
- Новые клиенты подключаются только к работающим серверам A и C
- Health-check автоматически исключает недоступный сервер

### Демонстрация автообнаружения серверов

**Шаги:**
1. Измените `balancer-config.json`, добавив новый сервер:
   ```json
   { "serverId": "D", "host": "localhost", "port": 9004 }
   ```

2. Запустите новый сервер:
   ```bash
   java -cp build/libs/* ru.hse.drip.systems.distributed.seminar.i3.ChatServerMain D 9004
   ```

3. Подождите 30 секунд

**Ожидаемый результат:**
- Балансировщик автоматически обнаруживает новый сервер
- В логах: "живых=3" (или 4, если предыдущий сервер восстановлен)
- Клиенты могут подключаться к новому серверу

## Часть 2: Межсерверная синхронизация

### Демонстрация распространения сообщений

**Шаги:**
1. Убедитесь, что все компоненты запущены (балансировщик + 3 сервера)
2. Подключите клиентов к балансировщику (они будут распределены по серверам):
   ```bash
   # Терминал 1 - клиент 1
   java -cp build/libs/* ru.hse.drip.systems.distributed.seminar.i3.ChatClient
   
   # Терминал 2 - клиент 2  
   java -cp build/libs/* ru.hse.drip.systems.distributed.seminar.i3.ChatClient
   
   # Терминал 3 - клиент 3
   java -cp build/libs/* ru.hse.drip.systems.distributed.seminar.i3.ChatClient
   ```

3. Отправьте сообщения от разных клиентов (просто введите текст в терминале клиента):
   ```
   # От клиента 1
   Hello from server A!
   
   # От клиента 2
   Hi from server B!
   
   # От клиента 3
   Greetings from server C!
   ```

**Ожидаемый результат:**
- Все клиенты получают все сообщения, независимо от сервера подключения
- В логах серверов видны peer-соединения и пересылка сообщений
- Сообщения доставляются в том же формате, что и отправлены
- Клиенты отправляют простые текстовые строки, JSON используется только между серверами

### Демонстрация дедупликации

**Шаги:**
1. Отправьте одинаковое сообщение от нескольких клиентов одновременно
2. Проверьте логи серверов

**Ожидаемый результат:**
- Каждое сообщение доставляется только один раз каждому клиенту
- В логах `DedupStore` видна фильтрация дубликатов по `messageId`
- Периодическая очистка устаревших ID каждую минуту

### Демонстрация обновления списка узлов

**Шаги:**
1. Остановите один сервер
2. Подождите 10 секунд (health-check)
3. Проверьте логи серверов

**Ожидаемый результат:**
- В логах серверов: "получен новый список серверов"
- Peer-соединения перестраиваются автоматически
- Удаляются соединения с недоступными серверами

## Часть 3: Отказоустойчивость клиента

### Демонстрация автоматического переподключения

**Шаги:**
1. Подключите клиента:
   ```bash
   java -cp build/libs/* ru.hse.drip.systems.distributed.seminar.i3.ChatClient
   ```
2. Отправьте несколько сообщений (просто введите в терминале клиента):
   ```
   Test message 1
   Test message 2
   ```
3. Остановите сервер, к которому подключен клиент (Ctrl+C в терминале сервера)
4. Продолжайте отправлять сообщения:
   ```
   Message after server crash
   Another message
   ```

**Ожидаемый результат:**
- Клиент выводит: "Соединение потеряно. Переподключение через 10 секунд..."
- Сообщения сохраняются в очереди
- Через 10 секунд клиент автоматически переподключается к балансировщику
- Балансировщик перенаправляет клиента на другой живой сервер
- Сохраненные сообщения отправляются автоматически

### Демонстрация Graceful Degradation

**Шаги:**
1. Остановите все серверы (Ctrl+C во всех терминалах серверов)
2. Попробуйте подключить клиента:
   ```bash
   java -cp build/libs/* ru.hse.drip.systems.distributed.seminar.i3.ChatClient
   ```
3. Отправьте сообщение (просто введите в терминале клиента):
   ```
   Message when no servers available
   ```

**Ожидаемый результат:**
- Клиент получает: "Нет доступных серверов. Повтор через 10 секунд."
- Сообщения сохраняются в очереди
- Каждые 10 секунд клиент повторяет попытки подключения к балансировщику

4. Запустите один сервер:
   ```bash
   java -cp build/libs/* ru.hse.drip.systems.distributed.seminar.i3.ChatServerMain A 9001
   ```
5. Подождите до следующей попытки подключения (до 10 секунд)

**Ожидаемый результат:**
- Клиент успешно подключается к балансировщику
- Балансировщик перенаправляет клиента на восстановленный сервер
- Все сохраненные сообщения отправляются


## Критерии 

### Задача 1 (3 балла)
- Round-Robin распределение клиентов
- Health-check исключает недоступные серверы  
- Автообнаружение серверов из конфига

### Задача 2 (4 балла)
- Сообщения доставляются всем клиентам
- Дедупликация работает корректно
- Peer-соединения перестраиваются при изменениях

### Задача 3 (3 балла)
- Автоматическое переподключение при сбоях
- Graceful degradation при недоступности серверов
- Прозрачность для пользователя (без остановок)

## Возможные проблемы и решения
### Проблема: Порт уже используется
**Решение:** Остановите все Java процессы:
```bash
taskkill /f /im java.exe
# Или находим процесс по порту:
netstat -ano | findstr :9999
taskkill /f /pid <PID_номер>
```

### Проблема: Неизвестные клиенты подключаются
**Решение:** Проверьте активные процессы и остановите лишние:
```bash
# Просмотр всех Java процессов
tasklist | findstr java

# Просмотр подключений к балансировщику
netstat -ano | findstr :9999

# Остановка всех процессов
taskkill /f /im java.exe
```

### Проблема: Клиенты не отключаются
**Решение:** Принудительная остановка:
```bash
# Остановить все Java процессы
taskkill /f /im java.exe

# Проверить, что все остановлено
tasklist | findstr java
# должно быть пусто)))))

# Если остались процессы, остановить по PID:
taskkill /f /pid <PID_номер>
```
### Проблема: Клиент не подключается
**Решение:** Проверка, что балансировщик запущен на порту 9999

### Проблема: Сообщения не доставляются
**Решение:** Проверка, что все серверы запущены и подключены к контрольному каналу

### Проблема: Health-check не работает
**Решение:** Проверка, что серверы слушают на правильных портах (9001, 9002, 9003)

### Проблема: Peer-соединения не устанавливаются
**Решение:** Проверка, что серверы могут подключаться к порту 9090 (контрольный канал)

### Проблема: Много "мертвых" соединений (CLOSE_WAIT/FIN_WAIT)
**Решение:** Это нормально для health-check, но можно проверить:
```bash
# Проверить состояние соединений
netstat -ano | findstr CLOSE_WAIT
netstat -ano | findstr FIN_WAIT

# Если слишком много - перезапустить систему
taskkill /f /im java.exe
./gradlew build
# Запустить заново
```

### Проблема: Утечка сокетов
**Решение:** Health-check создает временные соединения, которые могут накапливаться:
```bash
# Проверить детально по портам
netstat -ano | findstr :9001
netstat -ano | findstr :9002
netstat -ano | findstr :9003

# Перезапуск системы очистит все соединения
taskkill /f /im java.exe
```
